# 过程文件管理规范（_temp）

## 背景

多轮讨论产生的过程文件统一按本规范管理，并由收尾工作流登记进 temp 双层索引（`memory/temp_recent.md` / `temp_archive.md`），保证事后可定位。

## 目录结构

```
_temp/
└── 20260818/                ← 日期文件夹：YYYYMMDD，每天一个
    ├── 需求梳理/             ← 任务文件夹：简要命名，体现功能
    │   ├── README.md        ← 必备的说明文档
    │   ├── 需求初稿.md
    │   └── ...
    └── 数据清洗/
        ├── README.md
        └── ...
```

## 规则

1. **统一位置**：所有过程文件保存在项目根 `_temp/` 下；最终交付物按项目结构放到应放位置（方向级详细报告 → `memory/track_<方向>/`），不作为过程文件处理。
2. **日期文件夹**：每天一个，命名 `YYYYMMDD`；当天过程文件都放对应日期文件夹。
3. **任务文件夹**：每产生一批新过程文件，在当天日期下新建任务子文件夹，名称简要、体现功能（如 `需求梳理`、`数据清洗`）。
4. **必备 README.md**：每个任务文件夹必须含 `README.md`：工作目的、输入文件（附路径）、输出文件（附路径）、创建时间戳（精确到秒，格式 `YYYY-MM-DD HH:MM:SS`）。
5. **同步更新**：输入/输出变化时更新 README 并追加更新时间（同样精确到秒）。
6. **产生即登记**：新建任务文件夹的同时，在 `memory/temp_recent.md` 记录该文件夹详情（目的/输入/产出/关键结论一行/秒级时间戳），并在 `memory/temp_archive.md` 追加一行流水。登记动作由收尾工作流的「temp 登记」步骤兜底，但批次产生时就该做，勿攒到会话末尾。
7. **纳入 Git**：`_temp/` 改动按 Git 规范及时提交推送。
