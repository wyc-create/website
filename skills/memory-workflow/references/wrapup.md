# 会话收尾工作流

## 目标
会话结束前，把跨会话仍有价值的内容**分拣后**同步进记忆树，并登记本次过程文件。

## 步骤

1. **分支自查**：当前分支以 `git branch --show-current` 为准（卡片与 git 冲突时以 git 为准并修卡）。全部记忆与文件改动只落在本分支 worktree 内；需要动的共享主干文件（MEMORY.md 概况节、纪律、AGENTS.md、他人 track）只记录待办，留给 main 处理，不在分支上改。

2. **扫描会话**，提取：任务进度、确认的结论、重要决定及原因、失败方案及原因、关键文件修改、测试结果、未决风险、下一步。（每个条目 1-2 句摘要，细节留给落盘文档。）

3. **方向分拣（硬步骤）**：每条信息归入唯一方向 → 进度/决定/待办写该方向 `track_<方向>.md`；数字、踩坑、结果表等细节写 `track_<方向>/` 详细报告（文件名带日期，正文含精确到秒的时间戳）；仅跨方向成立的事实才进主干（概况/纪律类文件，且仍受主干上限约束）。一主题一文件，禁止两组信息合并进同一文件。

4. **temp 登记**：本次产生的每个 `_temp/<日期>/<任务>/` 文件夹：`temp_recent.md` 记详情（目的/输入/产出/关键结论/秒级时间戳），`temp_archive.md` 追加一行流水。temp_recent 超 3 个日期时，最老的压缩沉入 archive。

5. **harness 检查**：按纪律第 11 条——门槛不满足的不写；满足的先并条目后建文件。

6. **两自检（每文件写入后）**：①重读，两句能压成一句就压（纪律 12）；②主干文件对照 8KB/120 行，超限立即外移细节留指针（纪律 2）。

7. **更新 MEMORY.md**：新文件入索引；方向摘要行同步最新一句话状态。

8. **提交推送**：按 `references/git.md`，推本分支。

9. **汇报（增量）**：除 SKILL.md 统一项外，须报告——各条信息落到了哪个方向的哪个文件；temp 登记了几个文件夹；有无「留待 main 处理」的主干改动待办。
