# 定期维护工作流（动手模式）

## 目标
按共用问题清单对项目记忆树做一次完整维护，使记忆系统健康、精简、准确。

## 步骤

1. **前置**：确认当前分支——**共享主干文件（纪律、AGENTS.md、MEMORY.md 概况节、他人 track）的维护只在 main 上执行**；功能分支只维护本分支 track 与 harness。维护动作遵循「先体检、后动手」：可先跑 `references/health.md` 出清单，用户确认后再执行。

2. **按 `references/issues.md` 全部 16 项逐项检查**（判定标准与动作以该文件为唯一来源，动手时逐条对应其「建议动作」列）。

3. **拿不准的条目**：单独列出问用户，不自行删除。

4. **Git 状态**：全部维护完成后按 `references/git.md` 提交推送；在 main 上改动的共享文件须 `git merge main` 同步到各 worktree。

5. **汇报（增量）**：除 SKILL.md 统一项外，按「合并了什么 / 更新了什么 / 删除了什么 / 等待用户确认什么」四类分组。
