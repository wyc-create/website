# 会话恢复工作流

## 目标
新会话开始时，按两级协议从记忆树快速恢复上下文，避免无关信息干扰。

## 步骤

1. **分支身份确认（第 0 步）**：`git branch --show-current` → 核对 `memory/_branch.md`：无卡或卡内分支名与实际不符 → 当场建卡/修正再继续。卡片缺失是常态（本地文件不随合并传播），不算异常。

2. **读取项目指南**：读项目根 `AGENTS.md`（worktree 内即本分支版本），按「接手必读」执行；指向的记忆文件缺失时直说缺失，不猜测。

3. **只读主干**：读 `MEMORY.md`（概况 + 活跃方向清单），**不读 track 详情子夹、不读 temp_archive.md**。harness 只读本工具文件（纪律第 11 条）。

4. **向用户汇报并定向**：两三句话报告——项目概况、有哪些活跃方向、各方向一行摘要、本次建议。然后**必须询问用户：本次在哪个方向推进**。

5. **定向加载**：用户选定后，才读该方向 `track_<方向>.md`；需要细节再读 `track_<方向>/` 内文档（凭文档内秒级时间戳定位新旧）。

6. **诚实约束**：记忆中没有的内容明确说「没有记录」，不凭印象猜测。

7. **给出建议**：基于该方向的待办与最新进度，给出下一步建议。
