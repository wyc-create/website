# 长期记忆维护纪律（十四条）

1. **索引专用**：MEMORY.md 只做索引，不在索引里堆正文；固定三节——项目概况（2-3 句）、活跃方向（每方向一行摘要）、文件索引。
2. **软上限**：MEMORY.md 日常上限 150 行/20KB，勿逼近 200 行/25KB 加载上限；每个主干子文件上限 8KB/120 行。豁免（不计入默认加载，但须在 MEMORY.md 标注「上限豁免·默认禁读」）：`track_<方向>/` 详情子夹、`temp_archive.md`。超限动作固定：细节外移，记忆只留结论+指针，禁止先塞满再拆。
3. **单主题与写入分拣**：每个子文件一个主题。写入前先把本批信息按主题分组，一组一个文件，禁止两组合并进同一文件。
4. **方向分枝**：每个活跃方向一个摘要 `track_<方向>.md` + 同名详情子夹 `track_<方向>/`。摘要只放进度、关键决定、待办与指针，不放实验数字、踩坑细节、结果表；详情报告写子夹（不进 docs/、不进 _temp/），带精确到秒的时间戳。详情默认禁读，用户选定该方向后才读。
5. **temp 双层登记**：一级 `temp_recent.md` 只保最近 3 个日期文件夹详情，出现第 4 个时把最老的压缩沉入二级；二级 `temp_archive.md` 为全历史流水，只追加、超限豁免、默认禁读（仅用户明确回溯时读取，健康检查跳过其内容审计）。归属判据：答「在哪/有什么」进 temp 系统，答「结论/怎么办」进主干；两边都要时主干=结论+路径指针、temp=位置+内容摘要，禁止互抄全文。`_temp/` 每个任务文件夹产生即登记。
6. **先检索后写入**：写入前先检索现有记忆；能更新旧记录就不重复新增。
7. **弃旧从新**：新结论推翻旧记录时直接覆盖，禁止「旧版全文+作废声明+新版」三段式；至多留一行「⚠️曾误记 X，已修正，详见 <文档路径>」。更正留痕义务属于落盘报告/文档，不属于记忆。
8. **不重复存储**：Git、代码、项目文档中易重新获得的内容不抄进记忆；跨文件、主干与 temp 之间也禁止互抄全文，用指针。
9. **机密不写**：密码、密钥、Cookie、Token、私钥永不写入记忆。
10. **项目根目录存储**：全部记忆保存在当前已打开项目根目录的 `memory/`，不使用任何工具的默认全局记忆路径。
11. **与工具无关**：记忆描述事实与规则，不描述「某个工具怎么点」。判据——换一个 agent 工具读这条记忆：会被误导吗？会因「与我无关」而跳过吗？任一为「是」即拆到 `memory/harness_<工具名>.md`，索引行标 `[harness-specific]`，通用文件留一行指针。**写 harness 的准入门槛（两条同时满足才记录）**：①经过实测验证（非猜测、非一次性观察）；②其他工具不知道该事实会实际出错。禁止为记录身份或偏好建档；新事实先检查能否并入已有 harness 文件。**读取纪律**：接手先确认自身工具身份，只读本工具的 harness 文件。
12. **精简表述**：只留规则与关键判据，删展开举例、重复强调与铺垫语；每条规则只写一个方向，默认写正面（该怎么做），仅当不写禁令就会重犯时才加禁令，且禁令不复述正面已给的信息；写入后重读，两句能压成一句就压。实验记录（数字/结论/里程碑）属事实性内容，不得因精简删改。
13. **分支身份**：记忆正文不写「当前在哪个分支」——分支身份只存在于 `memory/_branch.md` 本地卡片（git 未跟踪，故合并物理上不会污染它）。日常记忆与文件改动只在本分支进行，禁止跨 worktree 读写对方文件来「同步记忆」；共享主干文件只在 main 改。合并记忆的唯一通道是 git merge + 合并后主干对账（见 `references/git.md`）。
14. **回流机制**：项目实例 `memory/discipline.md` 对本模板可删不可加；新增条款须先提回模板评审，通过后随 skill 版本升级下发。模板每次变更 bump frontmatter `version`，并同步项目内 `skills/` 副本与各工具全局安装副本；发现三者不一致，以 AGENTS.md 与模板为准并记录差异。
